# AI助手网页服务

面向制造内网的 AI 助手服务台，包含知识问答、文档翻译、PDF 转 Word 和标准解读功能。

## 本地启动

1. 复制配置文件：

   ```powershell
   Copy-Item .env.example .env
   ```

2. 修改 `.env`：

   - `ADMIN_USERNAME` / `ADMIN_PASSWORD`：管理员账号密码。
   - `QA_API_BASE_URL`：知识问答助手平台主机地址，例如 `https://pan.wst.com:443`。
   - `QA_BOT_ID`：制造一厂知识问答助手 bot id，默认已填需求文档中的 id。
   - `QA_AUTH_CLIENT_ID` / `QA_AUTH_CLIENT_SECRET`：调用 `/api/authentication/v1/access_token` 所需的 Basic Auth 信息。
   - `QA_DEFAULT_ACCOUNT`：可选，仅用于不是从 OA 入口访问时的本地测试账号。
   - `QA_TLS_REJECT_UNAUTHORIZED=false`：仅当内网知识问答平台证书不被 Node.js 信任时用于测试。
   - `RAGFLOW_CHAT_URL`：制造四厂 RAGFlow 共享聊天的完整地址，包含认证参数，只写入 `.env`，不要提交到 GitHub。
   - `AI_MODEL_API_URL`：翻译、PDF 转 Word和标准解读共用的内网模型接口。
   - `AI_MODEL_NAME`：模型名称，当前为 `Qwen-Lite`。
   - `AI_MODEL_API_KEY`：模型接口 Bearer 密钥。
   - 外网调试界面时可临时设置 `MOCK_AI=true`。

3. 启动开发服务：

   ```powershell
   npm run dev
   ```

4. 浏览器打开：

   ```text
   http://localhost:5173
   ```

## 人员、登录与权限

1. 在 `.env` 中配置生产人事接口：`MDM_API_BASE_URL`、`MDM_CLIENT_ID`、`MDM_CLIENT_SECRET`。真实凭据只保存在 `.env`，不提交版本管理。
2. 使用原 `admin` 账号和服务器配置的管理员密码登录，进入“权限中心 → 用户管理”，点击“同步人员与部门”。首次同步需在内网进行。
3. 同步后员工可从门户免密进入；工号与 OA 账号一致。手动密码登录的新账号初始密码为 `123456`，首次密码登录必须修改密码。
4. 在“角色管理”中为员工分配超级管理员、翻译术语库管理员或一厂、二厂、三厂提示词管理员。一个人可拥有多个角色。
5. 用户管理按真实公司与完整组织树分组，下级默认收起、可逐级展开。点击父部门默认包含下属人员，员工与角色成员显示实际部门路径；不显示在职状态。

每周一北京时间 04:00 自动同步；首次成功同步后才启用自动同步。同步保留已有密码和角色。缺工号或人员编号的记录单独隔离，一致重复合并，姓名为空时保留旧姓名或用工号显示；用户管理提供异常明细。含隔离记录时不自动停用原账户或部门。网络失败、分页不完整或全部人员不可用时保留原数据。诊断写入 `storage/logs/mdm-sync.log`。

普通员工登录后可以使用所属部门的知识助手和其他通用助手、提交反馈。首页、统计和反馈列表可公开浏览，反馈默认收起、最新优先、每页 3 条，仅超级管理员可以回复。新反馈记录提交时的姓名与完整部门路径；员工调动后不改写旧反馈身份，旧反馈未记录提交人时不推测或补造姓名。

月度、年度统计默认显示当前周期，并支持历史查询；每月 1 日、每年 1 月 1 日北京时间 04:00 归档上一周期，服务启动后补做遗漏归档。默认汇总公司，选择公司后显示其一级部门，点击部门查看下级；使用次数按点击助手入口计数，新事件保存当时公司、实际部门和祖先路径。旧记录与旧归档不改写，没有公司快照的旧事件保留为历史归属，不推测当时公司或车间。

完整组织升级会先备份数据库到 `storage/backups/before-organization-v2-*.sqlite`。本机若有成功采集的原始快照，首次启动自动据此恢复组织归属，无需联网；只迁移已有员工的组织字段，保留密码、账号、角色与会话。没有快照时请在内网手动同步一次。迁移仅执行一次，后续以正常人事同步为准。

员工使用一厂知识问答时，后端直接使用其已登录账号获取知识助手 Token。系统管理员可继续使用 `.env` 的 `QA_DEFAULT_ACCOUNT` 或原 OA 入口的 `code` 参数测试：

```text
http://localhost:5173/?code=base64后的OA账号
```

此参数只用于系统管理员的一厂问答身份，不作为本平台登录凭据。

## 知识助手组织范围

西部超导材料科技股份有限公司（公司编号 `100`）的原规则保留：一厂（部门 `189`）及其下属组织只显示一厂助手；四厂（`192`）及其下属组织只显示四厂助手；本公司信息技术部（`174`）和高管（`193`）及其下属组织可见全部现有知识助手。另外，西安聚能超导线材科技有限公司（公司编号 `500`）全员可见四厂助手，不限部门或职位，但不会获得一厂助手。未明确授权的其他公司的同名厂、信息技术部或高管不混入；尚无对应助手的组织显示暂无可用助手。

首页知识区与顶部“问答”均由后台 `/api/me` 返回的同一份 `knowledgeAssistants` 列表生成。顶部在只有一个助手时直接进入，多个助手时显示选择页；展开分区或进入选择页不计使用次数。接口、统计入口及四厂备用外链同样校验归属，不能靠手工访问隐藏接口绕过。

组织判断使用同步后的真实公司和实际部门祖先，不使用页面参数、客户端姓名、辅助 `deptTopId` 或路径字符串推测身份。每个请求重新读取当前员工资料，成功人事同步后新请求立即按新归属处理。内置 `admin` 保留全部入口便于维护；给员工分配内容管理或超级管理员角色本身不会扩大知识问答范围。

助手的标题、简介、图标及所属公司/部门统一登记在 `server/knowledge-assistants.js`。后续增加二厂、三厂或其他部门助手时，连同其实际聊天适配与使用统计一起登记，首页与顶部列表无需重复手写卡片。不提前显示尚未实现的助手。本次不限制翻译、PDF 或标准解读助手。

## 门户单点登录

平台作为客户端，入口为 `/sso/login`。门户带 `ticket` 跳转到该中转页面；前端同源调用 `GET /api/sso/login`，后端通过 `SSO_CHECK_TICKET_URL` 校验后，将返回的 `data` 账号匹配到已同步且未停用的员工。校验失败不建立登录；没有对应账号时按协议跳转 `SSO_FORBIDDEN_URL`。

当前服务器入口为 `http://172.28.200.66/sso/login`。门户负责构造单点地址，不需要用户提供门户授权链接。前端与 API 均用相对地址，内网认证地址由服务器 `.env` 读取，复制到 Windows 服务器后不依赖开发电脑路径。

版本化的 Nginx SSO 路由片段位于 `deploy/nginx-sso.conf`，已同步到本机发布模板 `E:\Qwen-cc\nginx-1.23.2\conf\nginx.conf`。打包时保留这些路由与专用错误响应；不要仅更新 Node 后端而继续使用旧前端或旧 Nginx 配置。新发布包仍需统一生成后才能部署到服务器。

门户登录沿用员工已有角色与部门，免去本平台初始密码提示，不修改本平台密码或首次改密标记；手动密码登录仍要求改密。固定密码 `sysAdmin` 不会用于认证，也不收集 OA 密码。内置系统管理员保留手动密码登录，不通过门户映射。

`SSO_ENABLED` 默认启用，`SSO_CHECK_TICKET_URL` 默认为 `http://192.168.50.87:8888/sso/checkTicket`，无账号时跳转 `http://192.168.50.87:8888/403`；校验超时默认 15 秒。日志位于 `storage/logs/sso-login.log`，只记录请求编号、阶段、耗时与错误代码，不记录 ticket、密码或认证响应。成功验证过的 ticket 哈希保存在 SQLite，防止本平台重复使用。

用户从门户入口进入无需再次输入密码；直接打开平台首页仍可手动登录。退出登录只退出本平台，目前协议不包含跨系统单点注销。正式门户联调需在 Windows 服务器能够访问认证中心的内网环境中完成。

## 四类翻译术语库

术语分为通用、成品检查、理化检验、加工工序四类。对话与 Word 翻译共享下拉选择，未提供选择时默认通用；直接翻译后，润色和最终质检只使用该库，不叠加其他库。文件任务在提交时固定词库快照，管理员中途更新不会改变已开始任务。

术语管理员及超级管理员可按库搜索中文、英文和备注，逐条或批量新增、修改、删除。同库中文或英文重复时，展示匹配记录的完整中英文，可返回修改或明确选择“仍然录入”；不会自动覆盖原条目。英文不区分大小写、首尾空格忽略，不同库可重复；批量编辑排除被编辑记录的旧值、按最终结果检查，写入采用事务。

首次升级会备份旧数据库到 `storage/backups/before-glossary-libraries-*.sqlite`，旧术语 id、内容、备注、创建和更新时间保持不变，全部归入通用库，旧重复记录不删除。SQLite 仍是数据源，后台同步 `storage/glossaries/general.md`、`finished.md`、`testing.md`、`processing.md`，保留旧 `storage/glossary.md` 为通用镜像；不应靠直接改 Markdown 修改词库。

翻译结果不显示词条数量。来源提示后的“点击查看”紧邻文字，新窗口通过登录保护的 PDF 接口预览 SS020101。私有文件存于 `resources/standards/ss020101-a3.pdf`，随 Windows 包发布，不放用户 storage、不提交 GitHub、不自动导入全部 PDF 术语。

## 新增助手

- 制造一厂知识问答：继续使用 OA 身份和云盘知识问答接口，支持流式回答及原文引用。
- 制造四厂知识问答：通过已确认的 `chats_openai` 接口在平台内流式回答，保留“在 RAGFlow 中打开”备用入口。
- PDF 转 Word：逐页提取 PDF 文本；文本过少时自动将该页渲染为图片交给模型识别，最终将统一的 Markdown 源文本写入可下载的 DOCX。
- 标准解读（一厂）：读取 DOCX 文档，依据管理员维护的提示词分段解读并生成 DOCX。
- 标准解读（二厂）和（三厂）：与一厂使用相同处理流程，并分别使用独立提示词配置。
- 管理员页面可编辑三个标准解读提示词，并检查最近模型响应是否包含 reasoning 字段或 `<think>` 标签。

共享模型的每次请求都会发送：

```json
"chat_template_kwargs": { "enable_thinking": false }
```

## 当前文档处理边界

DOCX 会尽量保留可解析的段落与表格结构。PDF 转 Word 的下载结果保留 Markdown 标题、列表、管道表格和公式源文本，不再强制转换为 Word 原生表格；低质量扫描件中无法确认的字符可能标记为“无法辨认”。`.doc` 文件请先另存为 `.docx` 后上传。
